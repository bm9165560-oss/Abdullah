# 🍔 Burger House — موقع مطعم برغر (نسخة عرض تجريبية)

موقع مطعم عربي كامل من اليمين إلى اليسار (RTL)، جاهز للعرض على أصحاب المطاعم والعملاء المحتملين.
يعمل فعلياً: قائمة طعام، سلة مشتريات مع حساب الأسعار ورسوم التوصيل، نموذج إتمام طلب مع تحقق من البيانات، ورسالة طلب جاهزة للإرسال عبر واتساب.

> ⚠️ **تنبيه مهم:** كل البيانات في هذا الموقع **تجريبية** — اسم المطعم، الأرقام، الأسعار، مواعيد العمل، والصور (صور مجانية من Unsplash) ليست لمطعم حقيقي. لا تُستخدم هذه النسخة لاستقبال طلبات فعلية قبل تعديل البيانات وإضافة رقم واتساب حقيقي.

---

## ١. التشغيل السريع

المتطلبات: **Node.js 18 أو أحدث** فقط. لا توجد أي حزم خارجية للواجهة (لا React ولا أدوات بناء).

```bash
# داخل مجلد المشروع
npm start
```

ثم افتح المتصفح على: <http://localhost:3000>

لتغيير المنفذ:

```bash
PORT=8080 npm start
```

`npm start` و`npm run dev` يشغّلان نفس الخادم (`node server.js`) — لا حاجة لإعادة بناء أي شيء بعد التعديل، فقط أعد تحميل الصفحة.

## ٢. الاختبارات

```bash
npm test        # اختبارات منطق السلة والحسابات ونموذج الطلب (Node، بدون متصفح)
npm run test:e2e  # اختبار متصفح حقيقي (Chromium) على مقاس هاتف وكمبيوتر
```

- `npm test`: ١٨ اختباراً تغطي إضافة/حذف/تعديل الكميات، حساب الإجماليات بالدينار، التوصيل المجاني، تنظيف البيانات المحفوظة، التحقق من الاسم والهاتف الأردني والعنوان، ونص رسالة واتساب.
- `npm run test:e2e`: يشغّل الخادم تلقائياً ثم ينفّذ على مقاسَي **390×844 (iPhone 13)** و**1440×900 (كمبيوتر)** سيناريو كاملاً: إضافة أصناف، تعديل الكميات، التحقق من ظهور 11.00 د.أ + 1.50 توصيل = 12.50 د.أ، إتمام الطلب، التحقق من الحقول، حفظ السلة بعد إعادة التحميل، وعدم وجود تمرير أفقي أو أخطاء JavaScript.

> لت شغيل اختبار المتصفح أول مرة على جهاز جديد (Ubuntu/Debian):
> ```bash
> npm install
> npx playwright install chromium
> sudo npx playwright install-deps chromium
> ```

## ٣. تغيير بيانات المطعم لاحقاً

كل شيء قابل للتعديل من ملفين فقط:

### أ) الإعدادات العامة — `public/js/config.js`

| الحقل | الوظيفة |
| --- | --- |
| `restaurantName` / `tagline` | اسم المطعم والشعار النصي |
| `whatsappNumber` | **رقم واتساب الطلبات** بالصيغة الدولية بدون `+` (مثال: `"962791234567"`). **فارغ افتراضياً بشكل مقصود** — عند تركه فارغاً يظهر تنبيه للعميل ولا يُرسل الطلب. |
| `phone` / `email` | رقم الهاتف والبريد في التذييل |
| `address` / `mapUrl` | العنوان ورابط الخريطة |
| `openingHours` | مواعيد العمل (تُعرض في التذييل) |
| `deliveryFee` | رسوم التوصيل بالدينار (افتراضياً `1.5`) |
| `freeDeliveryMinimum` | الحد الأدنى للتوصيل المجاني (افتراضياً `12`) |
| `currency` | رمز العملة (افتراضياً `د.أ`) |
| `demoNotice` | نص التنبيه بأن الموقع تجريبي |

### ب) الأصناف والأسعار — `public/js/menu.js`

كل صنف عنصر في مصفوفة `menu` بالشكل التالي:

```js
{
  id: "classic-burger",          // معرّف فريد (بالإنجليزية، يُستخدم في السلة)
  category: "burgers",            // burgers | sides | drinks
  name: "كلاسيك برغر",
  description: "لحم بقري طازج 120 غراماً ...",
  price: 4.5,                     // بالدينار الأردني، رقم فقط
  image: "/assets/images/classic.webp",
  imageAlt: "وصف الصورة لقارئ الشاشة",
  popular: true,                  // يظهر في قسم «الأكثر طلباً»
  badge: "الأكثر طلباً",           // اختياري
}
```

- لإضافة صنف جديد: أضف عنصراً جديداً بنفس الحقول.
- لتغيير التصنيفات: عدّل مصفوفة `categories` في أعلى نفس الملف.
- **لتغيير الصور:** ضع ملفاتك في `public/assets/images/` (يفضّل `.webp` بحجم أقل من 200 كيلوبايت، مقاس 800×600 للبطاقات و1200×800 للصورة الرئيسية) وحدّث مسار `image`، مع الحفاظ على `width`/`height` في HTML عند الحاجة لتجنّب اهتزاز التصميم أثناء التحميل.

### ج) تغيير اسم المطعم في الصفحة نفسها

اسم المطعم في الترويسة والوصف وعنوان الصفحة موجود في `public/index.html` (وسم `<title>` و`<meta name="description">` و`data-restaurant-name`) وفي `public/js/config.js`. لغرض العرض السريع لصاحب مطعم آخر، يكفي تغيير `restaurantName` في `config.js` ثم تعديل `<title>` في `index.html`.

## ٤. النشر (Deployment)

الموقع خادم Node بلا تبعيات، لذلك يناسب أي منصّة تدعم Node أو Docker:

### الخيار الأول — أي منصّة Node (Render / Railway / Fly.io / Koyeb …)

- أمر التشغيل: `npm start`
- المنفذ: المنصّة تمرّر متغير البيئة `PORT` والخادم يستخدمه تلقائياً ويستمع على `0.0.0.0`.
- لا حاجة لأمر بناء (لا يوجد `build`).

### الخيار الثاني — Docker (مُجهّز داخل المشروع)

```bash
docker build -t burger-house .
docker run -p 3000:3000 burger-house
```

- `Dockerfile` يستخدم `node:22-alpine`، ويشغّل الخادم بمستخدم غير جذري، ويحتوي فحص صحة على `/healthz`.
- `.dockerignore` يستثني `node_modules` والاختبارات لتقليل حجم الصورة.

### الخيار الثالث — استضافة ثابتة (Netlify / GitHub Pages / Cloudflare Pages)

مجلد `public/` هو موقع ثابت بالكامل، لذا يمكن نشره كما هو. ملاحظة: الروابط داخله مطلقة (`/css/...`) لذا انشره على نطاق جذري أو اضبط المسار `base` إن نشرته على مسار فرعي.

### الفحص بعد النشر
- افتح `/healthz` — يجب أن يعيد `ok`.
- أضف صنفاً للسلة وتحقق من ظهور الإجماليات، ثم جرّب إتمام طلب.

    ├── unit/cart.test.js     # npm test
    └── e2e.mjs               # npm run test:e2e

## ٦. قرارات تقنية

- **الأمان:** الخادم يضبط `Content-Security-Policy` صارمة (كل الموارد محلية، لا سكربتات خارجية) ورؤوس `X-Content-Type-Options` و`Referrer-Policy` و`Permissions-Policy`.
- **الأداء:** لا توجد مكتبات JS خارجية، الصور بصيغة WebP محلية، الخطوط محلية مع `font-display: swap` و`preload` للصورة الرئيسية، وضغط gzip للنصوص.
- **الحسابات:** الأسعار تُحسب داخلياً بالسنت (`cents`) لمنع أخطاء الفاصلة العائمة، ثم تُعرض بالدينار برقمين عشريين.
- **إمكانية الوصول:** عناصر دلالية، تسميات `aria`، إدارة التركيز في درج السلة، رسائل خطأ مرتبطة بالحقول، احترام `prefers-reduced-motion`، وتباين ألوان مناسب.
- **بدون رقم واتساب افتراضي:** لتجنّب إرسال طلبات لعرض تجريبي إلى رقم حقيقي، يظهر تنبيه بدل زر الإرسال حتى يُضبط الرقم في `config.js`.

## ٧. ما لا يفعله الموقع

- لا يوجد دفع إلكتروني أو بوابة دفع.
- لا يوجد حساب مستخدم أو لوحة تحكم أو قاعدة بيانات — الطلب يُرسل كرسالة واتساب مكتوبة يدوياً.
- لا تتبّع حالة الطلب أو الطلبات السابقة (السلة تُحفظ محلياً في `localStorage` فقط).
